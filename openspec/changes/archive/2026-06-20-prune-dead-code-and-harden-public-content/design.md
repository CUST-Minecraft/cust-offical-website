## Context

官网前台已经通过 Nuxt Server Routes 的 `/api/public/*` 读取 Strapi 公开内容，`docs/总体设计文档.md` 和 `docs/详细设计文档.md` 明确生产环境不得用 mock 内容冒充真实 CMS 数据，CMS 不可用或维护模式开启时应进入维护态。代码审查报告中成立的问题集中在三类：

- 维护模式和公开内容接口之间缺少统一阻断，导致管理员开启维护后部分内容接口仍可能继续返回真实内容。
- Strapi 适配层和前端展示组件存在边界不一致，例如 Activity 可选字段未完全字符串化、外部服务图标白名单缺少已配置服务图标。
- 富文本链接渲染、日期格式化、populate 迁移错误判断和组件局部变量存在重复或死代码，长期会增加误改概率。

相关 docs 已经支持本次方向，没有发现需要推翻的产品范围。本变更只需要在实现完成后检查是否要补充 `docs/开发规范文档.md` 中关于富文本链接和代码卫生的说明。

## Goals / Non-Goals

**Goals:**

- 让公开内容接口在维护模式开启时统一返回维护态。
- 保持维护页、站点设置、外部服务和服务状态接口在维护态下仍可读取最小展示所需数据。
- 让 Nuxt BFF 输出的公开内容字段符合稳定前台契约，不泄漏 Strapi 原始对象或非预期类型。
- 加固富文本链接渲染，阻断 `javascript:` 等非安全协议。
- 清理重复日期格式化、重复错误判断、未使用 refs/props 和失效 mock 导出。

**Non-Goals:**

- 不新增自研后台、权限系统、登录态或 `/api/member/*`。
- 不修改 Strapi content-type，不新增数据库字段。
- 不把审查报告中不成立的项目纳入实现，例如公告 `featuredOnly` 参数、成员精选去重逻辑、列表错误一律转为空状态。
- 不引入 Redis、KV、服务端持久 last-known-good 缓存或新的运行时依赖。

## Decisions

### Decision: 使用内容接口级维护守卫

在 Nuxt server utils 中提供一个公开内容守卫，由首页、社团介绍、活动、公告、动态、成员和加入页等内容接口在读取业务内容前调用。

```
公开内容请求
    │
    ▼
读取 maintenance-page
    │
    ├─ enabled = true  ──▶ MAINTENANCE / 503
    │
    ├─ Strapi 不可用
    │      ├─ 生产环境 ──▶ MAINTENANCE / 503
    │      └─ 开发环境 ──▶ 允许继续走开发 fallback
    │
    └─ enabled = false ──▶ 读取目标公开内容
```

选择接口级守卫而不是页面级跳转，是因为维护模式属于公开 API 契约的一部分；这样前台页面、搜索索引和直接访问 API 都能得到一致语义。维护页、设置、外部服务和服务状态接口不使用该守卫，因为它们是维护态页面自身渲染所需的最小数据来源。

### Decision: 在 Strapi 适配层收敛公开字段类型

Activity 的 `endTime`、`location`、`signupUrl` 等可选字段统一通过字符串归一化函数输出。外部服务图标继续使用允许列表，但允许列表必须覆盖当前 docs 和模型中已经存在的公开服务入口，例如 `agent`。

备选方案是在页面组件内分别容错。该方案会让每个页面都理解 Strapi 原始结构，违背 Nuxt BFF 负责字段裁剪和标准化的边界。

### Decision: 富文本链接先校验 URL 再输出 HTML

富文本渲染继续保持轻量实现，不引入新的 Markdown/XSS 依赖。链接解析时先处理原始文本段，链接文本和普通文本分别转义，href 使用 `URL` 校验，仅允许 `http:` 和 `https:`。无效链接作为普通文本展示。

备选方案是整体引入 sanitization 库。当前正文渲染能力有限，本次只修复链接协议风险；后续如果支持更完整 Markdown 或 HTML，应单独规划可信渲染方案。

### Decision: 把重复工具函数集中到最小公共模块

页面日期展示使用共享格式化工具，Strapi populate 迁移错误判断使用单一 helper。删除不参与逻辑的 refs、`void props` 和失效 mock 导出，避免未来维护者误以为这些变量仍承担行为。

## Risks / Trade-offs

- [Risk] 每个内容接口都要显式接入维护守卫，漏接会导致行为不一致。→ 通过任务清单覆盖所有 `/api/public/*` 内容接口，并在验证时搜索调用点。
- [Risk] 维护守卫读取 `maintenance-page` 会增加一次 CMS 请求。→ 该请求只发生在公开内容 BFF 层，且维护态是站点级控制；后续可结合 HTTP 缓存优化，但本次不引入持久缓存。
- [Risk] 富文本链接仅允许 `http`/`https` 会让 `mailto:` 等链接变为普通文本。→ 当前 docs 未要求支持邮件协议；如未来需要，应在 specs 中明确允许协议后再扩展。
- [Risk] 清理死代码可能误删潜在预留点。→ 只删除无引用、无运行时作用且可由类型检查覆盖的局部代码或 mock 导出。

## Migration Plan

1. 新增公开内容维护守卫并接入所有内容型 `/api/public/*` 接口。
2. 调整 Strapi 适配层字段归一化和图标允许列表。
3. 加固富文本链接渲染。
4. 抽取共享日期格式化与 populate 迁移错误 helper，删除死代码。
5. 运行 TypeScript/Nuxt 类型检查，并使用搜索确认旧重复函数和死代码已清理。

回滚时可按上述模块逆序回退。由于不修改数据模型和数据库，回滚不需要数据迁移。

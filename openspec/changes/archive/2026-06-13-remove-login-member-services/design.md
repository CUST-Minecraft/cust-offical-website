## Context

当前官网实现了 `/login`、`/member`、`/member/skin`、`/member/admin` 和 `/api/member/*`，但这些能力只基于 mock 当前账号和 mock 角色判断，并没有真实注册、登录、会话、权限或账号体系。原始设想是让社员先在官网登录，再按角色跳转到皮肤站或 CMS；实际业务边界已经变化：皮肤站是独立系统，CMS 管理员可以直接访问后台，下载服务由 QQ 群等社群渠道承接。

因此，本次设计把官网从“公开站点 + 登录社员服务层”收敛为“公开展示站点 + 外部服务引导”。Header 原登录按钮位置改为皮肤站外链按钮，复用当前地狱门图标，点击后直接跳转到配置的皮肤站网址。这会影响页面路由、Header、搜索快捷项、Nuxt server routes、前端类型、mock 数据、Strapi 预留资源模型和 docs 文档。

## Goals / Non-Goals

**Goals:**

- 删除官网内没有真实业务意义的登录、注册、社员中心、角色权限跳转和 mock 当前用户能力。
- 保留公开内容能力，包括首页、社团介绍、活动、公告、动态、公开社员介绍、加入我们、维护页、错误页、搜索和服务状态。
- 让皮肤站作为独立外部系统存在。官网在 Header 原登录按钮位置展示“皮肤站”外链按钮，只进行公开外链引导，不做官网登录态校验。
- 让 CMS 作为独立内容管理系统存在。管理员直接访问 CMS，不通过官网社员中心转发。
- 从官网和 CMS 预留模型中移除资源下载能力，下载分发改由 QQ 群等社群渠道完成。
- 同步更新 docs，避免文档继续描述已删除的登录、社员权限和资源下载范围。

**Non-Goals:**

- 不实现新的认证系统、统一身份、OAuth、账号注册或会话管理。
- 不改造皮肤站登录系统，也不让皮肤站账号与官网互通。
- 不实现新的 CMS 权限管理；CMS 权限仍由 Strapi 或后续后台系统自行承担。
- 不实现官网资源下载页、公开资源接口或文件托管能力。
- 不删除 `/members` 公开社员介绍页；它属于公开展示内容，不属于登录后的 `/member` 社员中心。

## Decisions

### Decision 1: 彻底移除官网登录层，而不是隐藏入口

选择删除 `/login`、`/member` 页面族、`/api/member/*` 和相关类型/mock 数据。

备选方案是仅隐藏 Header 登录按钮并保留路由，但这会让无入口功能继续积累维护成本，也可能被搜索、旧链接或站点地图暴露。彻底移除更符合新的产品边界。

### Decision 2: Header 原登录位置改为皮肤站外链按钮

官网不再通过 `/member/skin` 做受权限保护的中转。Header 原登录按钮位置改为“皮肤站”按钮，继续使用当前登录按钮的地狱门图标，点击后直接跳转到配置的皮肤站网址。按钮语义应从“登录”改为“皮肤站”，使用普通外链行为而不是 `NuxtLink` 指向站内登录页。

备选方案是完全移除 Header 右侧入口，或保留 `/member/skin` 作为无权限校验的跳转页。完全移除会降低皮肤站可发现性；保留站内中转页会延续 `/member` 命名和社员中心心智。Header 直接外链更清晰，也保留了原按钮位置的操作价值。

### Decision 3: CMS 后台入口不再出现在官网社员服务中

官网不提供 `/member/admin` 或“登录后进入内容后台”。管理员通过部署环境、内部文档或浏览器书签直接访问 Strapi Admin。

备选方案是在公开页放置 CMS 后台入口，但这会把管理入口暴露给普通访客，即使 CMS 自身有权限保护，也会增加噪音和攻击面提示。

### Decision 4: 删除资源下载规划和 Strapi resource 预留模型

资源包、整合包、地图和文件分发由 QQ 群完成，不再作为官网内容模型和前台能力预留。实现时应删除 `strapi-models/src/api/resource` 及 tag 与 resource 的关联，并同步更新模型说明。

备选方案是保留 resource 模型但不做前台页；这会让 CMS 中继续出现不使用的内容类型，后续维护者容易误以为官网下载站仍在规划中。

### Decision 5: 文档与实现一起收敛

本次变更必须同步修改产品需求、总体设计、详细设计、自研后台设计和 Strapi 模型说明。当前 docs 中大量内容仍以“官网登录后进入皮肤站/CMS/下载”为前提，不同步更新会让后续实现继续被旧设计牵引。

## Risks / Trade-offs

- [旧链接访问 `/login` 或 `/member/*` 变成 404] → 接受该结果；这些入口没有正式业务价值。必要时可在部署层或 Nuxt 中单独添加重定向，但本变更默认不保留兼容路由。
- [皮肤站入口从登录后服务变成 Header 公开外链后，普通访客也能看到入口] → 皮肤站本身是独立系统，应由皮肤站自行处理登录和访问控制；官网按钮文案使用“皮肤站”而不是“登录”，避免暗示官网账号体系。
- [删除资源模型影响未来下载站扩展] → 如果未来重新需要官网下载，应作为新的 OpenSpec change 独立设计资源模型、文件托管、安全和更新流程。
- [文档更新范围较大，容易漏掉旧表述] → 任务中加入全文检索检查，至少覆盖 “登录”“社员中心”“/api/member”“资源下载”“皮肤站控制台入口” 等关键词。

## Migration Plan

1. 删除登录和社员服务相关页面、API、类型、mock 数据和内部链接。
2. 将 Header 原登录按钮改为皮肤站外链按钮，复用地狱门图标，使用配置的皮肤站网址。
3. 清理搜索快捷项、composables 和 TypeScript 引用，确保构建不再引用 `/login`、`/member` 或 `/api/member/*`。
4. 删除资源下载相关 Strapi 预留模型和 tag 关联，更新模型说明。
5. 更新 docs 中的产品范围、架构图、接口清单、页面详细设计、权限说明、缓存规则和第一阶段状态。
6. 运行类型检查/构建，并用全文检索确认旧登录与下载服务叙事已移除或改写为外部系统说明。

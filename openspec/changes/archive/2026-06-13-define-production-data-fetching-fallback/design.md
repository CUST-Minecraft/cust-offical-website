## Context

当前官网已经形成 Nuxt 3 前台、`/api/public/*` Nuxt Server Routes、Strapi 5 CMS 的公开内容链路。`docs/详细设计文档.md` 已要求前台不直接调用 Strapi，并定义了 CDN 缓存建议、`MAINTENANCE`/503 错误语义和公开 API 字段裁剪规则。

现有代码中 `withMockFallback` 会在 Strapi 不可用时返回 mock 数据，这对本地开发有帮助，但如果生产环境沿用该策略，会让官网在内容源故障时展示示例数据。生产环境需要更诚实的降级方式：CDN 有缓存时继续返回缓存内容，CDN 无可用缓存且 Strapi 不可用时进入维护态。

## Goals / Non-Goals

**Goals:**
- 固化生产公开数据链路：CDN -> Nuxt BFF -> Strapi。
- 保留 CDN 作为第一阶段主要缓存层，通过 HTTP Cache-Control 承担公开页面、公开 API、媒体资源缓存。
- 禁止生产环境使用 mock 数据冒充真实内容。
- 在 Strapi 不可用、超时或连接失败时返回维护态，而不是误判为 404。
- 保证维护页有最小可用兜底内容，不依赖 Strapi 正常响应。
- 同步更新项目文档，使实现、OpenSpec 和 docs 口径一致。

**Non-Goals:**
- 不引入 Redis、KV、队列或新的外部缓存服务。
- 不实现服务端持久 last-known-good 缓存。
- 不改变 Strapi 内容模型和公开页面信息架构。
- 不引入自研后台、皮肤站代理或登录权限体系。
- 不实现服务端全文搜索或新的公开 API 资源。

## Decisions

1. **CDN 作为第一阶段主要缓存层**

   生产访问仍以 CDN 为第一层。首页和列表接口使用短缓存，详情接口使用中缓存，图片和附件使用长缓存。Nuxt BFF 负责为公开接口设置合理的缓存语义，具体缓存时长沿用 `docs/详细设计文档.md` 的规则。

   备选方案是应用层 Redis 缓存。该方案可以提供更强的源站兜底能力，但当前阶段会增加部署、监控和失效复杂度，因此暂不采用。

2. **生产环境禁用 mock fallback**

   mock 数据只服务开发和测试。生产环境下，Strapi 不可用时不得返回 mock 首页、mock 公告、mock 活动或 mock 站点配置。这样可以避免用户看到不真实内容，也避免运维误以为系统正常。

   备选方案是继续保留全环境 mock fallback。该方案开发体验更顺滑，但生产语义不可信，因此只保留在非生产环境。

3. **Strapi 不可用时进入维护态**

   当 CDN 无可用缓存且 Nuxt BFF 回源 Strapi 失败时，公开接口返回 `MAINTENANCE`/503 语义，页面进入维护态。Strapi 正常响应但内容不存在或未发布时，才返回 `NOT_FOUND`/404。

   备选方案是实现服务端持久 last-known-good 缓存。该方案可以在源站故障时展示旧真实内容，但需要定义持久存储、过期策略、污染防护和多实例同步。本阶段选择维护态，降低复杂度并保持内容准确性。

4. **维护页具备最小可用兜底内容**

   维护页和全局错误展示不能依赖 Strapi 成功返回才能渲染。站点配置获取失败时，应使用内置的最小站点信息和维护文案，保证用户能看到清楚的维护说明。

   备选方案是维护页也读取 Strapi 中的维护配置。该方案方便后台调整文案，但在 Strapi 故障时会导致维护页自身不可用，因此只能作为增强，不作为必要依赖。

5. **文档与实现同步**

   本变更会调整生产行为和缓存边界，需要同步 `docs/总体设计文档.md`、`docs/详细设计文档.md` 和 `docs/开发规范文档.md`。其中详细设计文档应记录生产错误语义和缓存策略，开发规范文档应记录 mock fallback 的环境边界。

## Risks / Trade-offs

- [Strapi 故障且 CDN 无缓存时官网不可展示公开内容] -> 使用维护页明确告知服务暂不可用；后续如可用性要求提高，再单独规划 last-known-good 或 Redis。
- [CDN 缓存可能短时间返回旧内容] -> 沿用短缓存和中缓存分层，并在内容发布流程中保留缓存刷新或等待自然过期的规则。
- [禁用生产 mock 后，本地开发体验可能受影响] -> 保留开发和测试环境 mock fallback，生产判断通过环境配置控制。
- [维护页依赖站点配置会形成循环故障] -> 维护页必须内置最小兜底文案和基础站点信息。
- [错误分类不清会把源站故障误报为 404] -> 在 Strapi 访问层区分连接失败、超时、无响应、业务无内容和正常空结果。

## Context

当前官网右下角入口已经从原始纵向按钮列表演进为居中的“快捷工具工作台”。该面板左侧展示文档中心、悦灵助手和社团服务状态，右侧展示当前工具内容。文档中心通过 `site.documentCenterUrl` 作为外部系统打开，悦灵助手通过 `/api/agent/status` 检查 Agent 服务状态，社团服务状态来自 `GET /api/public/settings` 的 `serviceStatus`。

这套实现解决了工具堆叠问题，但“快捷工具”命名仍偏临时，无法表达这些入口是官网提供的正式社团服务；同时“社团服务状态”作为站内工具项会把状态信息和服务入口混在一起。用户已经明确希望以工作台作为整体隐喻，将入口重命名为“社团服务”，并让触发器只显示“x 项服务可用”，不提前展示具体服务特征。

当前 `docs/详细设计文档.md` 仍以“全站搜索与快捷工具”为标题，并描述左侧顺序为“文档中心 / 悦灵助手 / 社团服务状态”。现有 `openspec/specs/document-center-quick-tool/spec.md` 也保留“右下角快捷工具”“展开快捷工具”“点击文档中心入口直接打开”等旧表述。本次变更需要同步修正这些文档和主规格。

## Goals / Non-Goals

**Goals:**

- 将用户可见的“快捷工具”改为“社团服务”或“社团服务工作台”。
- 将右下角触发器重设计为工作台隐喻入口，显示工作台图标、主标题“社团服务”和“x 项服务可用”。
- 在触发器未打开时提供轻微呼吸高光，强化可点击性，同时遵守减少动态偏好。
- 将服务列表收束为实际可进入的服务：文档中心和悦灵助手。
- 将服务状态从左侧服务列表移到面板级独立位置，优先放在标题栏右侧。
- 简化悦灵助手离线态，移除“查看公告”“查看维护说明”等 fallback 按钮，只说明不可用状态和原因。
- 保持文档中心外部系统边界、未配置禁用态和安全新标签页打开行为。
- 同步更新 OpenSpec 主规格和 docs 文档中的旧“快捷工具”语义。

**Non-Goals:**

- 不新增真实 Agent 对话服务、知识库检索或 Agent 后端能力。
- 不接入真实 Minecraft 服务器在线状态查询。
- 不新增文档中心嵌入、代理、账号同步、权限控制或文档内容管理能力。
- 不改变 `GET /api/public/settings` 和 `/api/agent/status` 的数据契约。
- 不把服务状态计入“x 项服务可用”中的可选择服务数量。
- 不引入新的 UI 组件库或动画依赖。

## Decisions

### 决策 1：入口身份从“快捷工具”改为“社团服务”

右下角触发器、面板标题、可访问性标签和文档表述统一使用“社团服务”。“快捷工具”可作为代码迁移过程中的旧内部命名暂存，但用户可见文本和新规格应使用“社团服务”。

替代方案：继续叫“快捷工具”。该方案改动小，但不能表达文档中心和悦灵助手是官网统一提供的服务入口，也会让工作台设计像临时工具抽屉。

### 决策 2：触发器使用工作台图标和服务数量，不展示具体服务特征

触发器使用工作台方块风格图标作为整体隐喻，文本结构为“社团服务 / x 项服务可用”。这里的 `x` 统计左侧可选择服务入口，当前为文档中心和悦灵助手。触发器不展示书架、悦灵头像或其他具体服务特征，避免入口在打开前显得零碎。

替代方案：在触发器中展示文档中心和悦灵助手的小图标。该方案能直接暴露内部内容，但会削弱“工作台”作为集合入口的统一性，也让未来增减服务时触发器变得拥挤。

触发器在页面滚动到页尾时应动态抬升，保持位于页尾内容上方，避免遮挡页尾社交链接、版权或致谢文本。

### 决策 3：未打开时使用轻微呼吸高光

社团服务触发器持续展示按钮表面光亮，接近 Minecraft 附魔书的内发光和掠光感，提示其可交互。该效果不应主要表现为外边框发光。待机时使用流动光效；面板打开、hover/focus 时通过短过渡切换为稳定表面光；在 `prefers-reduced-motion: reduce` 下停止动画但保留静态光效。

替代方案：完全静态按钮。该方案最克制，但右下角入口容易被理解为状态组件或装饰。强动画也不合适，因为官网仍以信息阅读为主。

### 决策 4：服务状态是面板级状态入口，不是左侧服务项

左侧列表只展示访问者可选择并使用的服务入口。服务状态改为标题栏右侧的独立状态按钮或状态胶囊，展示在线计数或摘要，例如 `2/3 在线`。点击该状态入口应在工作台内容区展示完整服务状态面板，此时暂时隐藏左侧服务列表和右侧服务栏位的左右分栏，让服务状态信息占据整个面板内容区。状态面板只展示当前服务健康信息和返回服务列表操作，不提供“查看维护说明”等维护页跳转按钮。

每次从右下角触发器打开社团服务工作台时，应回到社团服务列表和当前服务栏位；即使上一次关闭前停留在服务状态面板，也不得在下一次打开时直接显示服务状态面板。

替代方案：放在左侧栏底部。该方案可行，但仍容易被误读为一个服务列表项。标题栏右侧更像面板全局健康状态，语义更稳。

### 决策 5：悦灵助手离线态只保留直接相关的恢复路径

悦灵助手离线态应只说明 Agent 当前不可用及其原因，不展示“查看公告”“查看维护说明”等 fallback 按钮。服务状态由标题栏入口独立承载，不在悦灵离线态中重复引导。

替代方案：继续保留“查看公告”和“服务状态”两个按钮。该方案入口多，但会让悦灵助手离线态变成泛导航区域，也与服务状态上移为面板级入口的设计重复。

### 决策 6：文档中心仍是外部服务，但语境改为社团服务工作台

文档中心在左侧服务列表中作为外部服务展示，选中后在右侧展示外部系统说明和跳转按钮。选择左侧项不直接跳转。配置 `documentCenterUrl` 时按钮新标签页打开并使用 `noopener noreferrer`；未配置时保留入口和禁用态。

替代方案：恢复点击文档中心项直接跳转。该方案路径更短，但会破坏工作台“先选择、再查看服务说明或执行动作”的模型。

## Risks / Trade-offs

- [Risk] “社团服务”范围比“快捷工具”更正式，未来可能被误解为包含账号、下载、报名等后台能力。→ 在 UI 和文档中限定当前服务为文档中心和悦灵助手，继续明确第一阶段不建设自研后台和下载服务。
- [Risk] 服务状态移出左侧列表后发现性下降。→ 在标题栏右侧持续显示在线计数，点击后直接在面板内展示完整服务状态信息。
- [Risk] 触发器只显示“x 项服务可用”可能不如具体服务名直观。→ 用工作台图标和面板标题建立集合入口心智，打开后再由左侧列表展示具体服务。
- [Risk] 呼吸高光过强会干扰阅读。→ 限制动画周期和亮度，打开面板、hover/focus 和减少动态偏好时停止或弱化。
- [Risk] 主规格仍保留旧“快捷工具”行为会影响后续实现。→ 本变更包含 `document-center-quick-tool` delta spec，并新增 `community-services-workbench` 主能力，实施后应归档或同步主规格。

## Migration Plan

1. 更新 docs 文档，将“快捷工具”章节改为“社团服务工作台”，并同步服务列表、状态入口和触发器文案。
2. 重构 `FloatingServiceStatus.vue` 的用户可见文案、工具数据结构和状态入口位置，保留现有数据来源。
3. 新增或替换工作台方块风格图标资产，更新触发器结构为“社团服务 / x 项服务可用”。
4. 调整 CSS 中触发器、标题栏状态入口、左侧列表、右侧栏位和移动端布局样式。
5. 添加未打开态呼吸高光，并在面板打开、hover/focus 和 `prefers-reduced-motion` 下停止或弱化。
6. 添加页尾避让逻辑，确保社团服务触发器滚动到页尾时不与页尾重叠。
7. 清理悦灵助手离线态按钮，确保不再展示“查看公告”或“查看维护说明”等 fallback 按钮，并移除服务状态面板中的维护页跳转入口。
8. 验证桌面端和移动端：触发器可点击性、面板状态入口、文档中心跳转、悦灵离线态、服务计数、页尾避让和减少动态偏好。

## Open Questions

- “x 项服务可用”中的 `x` 是否只统计可选择服务总数，还是排除未配置的文档中心？当前倾向统计可展示服务入口数量，但文案可根据禁用态调整。

## Why

当前 `/join` 页面内容以“加入说明、条件、流程、联系方式、服务器说明、FAQ”分散呈现，适合基础说明，但不够贴合社团长期开放加入的使用场景。潜在新成员更需要一条清晰的新手引导线：先理解能以什么身份加入，再知道通过什么方式联系社团，最后了解规则和常见问题。

本变更将“加入我们”页面重塑为以加入流程为主的公开引导页，降低新成员加入门槛，同时保持第一阶段不在官网内实现报名审核、白名单审核或账号系统的边界。

## What Changes

- 将加入我们页的信息架构调整为“加入流程 + 常见问题”。
- 将参与身份、加入方式、规则说明、联系确认和加入后的开始方式收敛到流程步骤中展示。
- 扩展 `ProcessStep` 内容组件，使流程步骤可维护结构化图片、图片说明、明细条目和可选动作入口。
- 保留 FAQ 作为页面末尾的解惑区，聚焦长期开放加入、是否新手友好、是否强制在线、白名单和隐私展示等问题。
- 保持加入申请、白名单审核和社员账号体系在官网外处理；官网仅展示公开引导和外部入口。
- 同步更新 `docs/产品需求文档.md`、`docs/详细设计文档.md` 和 `strapi-models/模型说明.md` 中关于加入我们页、内容模型和 `ProcessStep` 的描述。

## Capabilities

### New Capabilities

- `open-join-flow`: 定义长期开放加入页面的流程引导、参与身份、加入方式、规则说明、常见问题和第一阶段边界。

### Modified Capabilities

- `content-model-boundaries`: 扩展流程步骤内容模型边界，允许 `ProcessStep` 使用结构化图片、图片说明、明细条目和动作入口，同时继续禁止使用 Markdown 拼装流程结构。

## Impact

- 影响前台 `/join` 页面内容结构和视觉呈现。
- 影响 `GET /api/public/join` 返回数据结构，以及 `JoinPageData` / `ProcessStep` 类型定义。
- 影响 Strapi `join-page` single type 和 `shared.process-step` component schema。
- 影响 Strapi 到 Nuxt BFF 的规范化逻辑，尤其是流程步骤图片字段的 `{ src, alt }` 输出。
- 影响 mock 数据、Strapi 测试数据导入脚本和内容模型说明。
- 需要同步更新产品需求、详细设计和 Strapi 模型文档，避免文档仍描述旧的分散式加入页结构。

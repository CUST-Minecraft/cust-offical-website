## Context

变更前，全站快捷工具由 `frontend/components/FloatingServiceStatus.vue` 承载，以右下角 `<details>` 展开三项纵向按钮：文档中心、悦灵助手、社团服务状态。文档中心是独立外部系统，已由 `document-center-quick-tool` spec 约束外部 URL、禁用态、书架图标和搜索可发现性；悦灵助手和服务状态则通过旧二级弹窗呈现。

现有实现的优势是简单直接，但展示方式把外部跳转和站内弹出工具混在同一组大按钮里。随着快捷入口增加，右下角堆叠按钮会占用更多页面空间，也不利于表达“外部系统跳转”和“站内工具运行”两种完全不同的工具类型。本次设计参考 Minecraft 投影/交易设置类界面的左右栏模式，将快捷工具改为居中的工作台面板。

本次变更不改变 `GET /api/public/settings` 数据来源，不新增文档中心代理、文档托管、官网登录态或成员中心依赖。相关用户可见行为需要同步更新 `docs/产品需求文档.md`、`docs/总体设计文档.md` 和 `docs/详细设计文档.md`。

## Goals / Non-Goals

**Goals:**

- 将快捷工具从右下角展开按钮列表改为居中工作台面板。
- 使用左侧“图标 | 工具名称”列表承载工具选择，并用外部/站内分组或标记区分工具类型。
- 使用右侧工具栏位直接呈现站内工具的轻量 UI，包括悦灵助手常用交互和社团服务状态摘要。
- 对文档中心等外部工具，在右侧栏位展示明确的外部系统说明和跳转按钮。
- 保持文档中心外部系统边界、未配置禁用态、书架图标和搜索可发现性。
- 保持移动端可用，避免居中面板在小屏幕中产生横向溢出或难以点击。

**Non-Goals:**

- 不建设文档中心内嵌浏览、代理、账号同步、权限控制或文档内容管理能力。
- 不把悦灵助手真实对话服务、知识检索或完整 Agent 后端能力纳入本次范围。
- 不接入真实 Minecraft 服务器在线状态查询。
- 不引入新的 UI 组件库、外部依赖或复杂状态管理方案。
- 不改变 Header 皮肤站入口和全站搜索的核心数据来源。

## Decisions

### 决策 1：保留右下角触发器，打开居中工作台面板

快捷工具仍在右下角提供稳定入口，但点击后打开居中的面板，而不是在右下角展开工具列表。面板采用轻量遮罩、像素硬边框和投影/交易设置界面风格，帮助访问者把它理解为“选择并使用工具”的临时工作区。

替代方案：继续在右下角展开紧凑列表。该方案空间占用更小，但无法自然承载右侧内嵌 UI，也难以参考用户指定的投影设置类左右栏界面。

### 决策 2：左侧工具列表统一承载入口，右侧栏位承载工具内容

左侧列表项使用“图标 | 工具名称”的主要结构，并保留右侧辅助标记：外部工具使用跳转标记，站内工具使用面板/状态标记，服务状态可显示 `online/total`。工具列表保持文档中心、悦灵助手、社团服务状态的顺序，并可用“外部入口”“站内工具”弱分组强化类型差异。

右侧栏位根据当前选中工具切换内容。外部工具显示说明和跳转按钮；站内工具直接显示轻量 UI。这样用户无需先猜按钮行为，看到右侧内容就能理解“这个工具会离开官网”还是“这个工具在官网内运行”。

替代方案：左侧点击后立即执行工具。该方案交互更短，但会削弱左右栏模型，也无法在执行前明确展示外部跳转提示。

### 决策 3：站内工具内嵌到右侧栏位，不再打开额外弹窗

悦灵助手和社团服务状态应在右侧栏位中展示适合快捷面板的版本。悦灵助手先检查 `/api/agent/status`，检测中展示连接提示，未配置或不可用时直接展示不可用提示和 fallback 操作，可用时展示常用指令、简短消息和输入区；服务状态可展示摘要、服务列表或重点状态和维护说明入口。站内工具在快捷工作台中完成查看和操作，不再从工作台跳转或打开额外弹窗，避免 Agent 未配置、服务状态等信息被重复展示。

替代方案：保留二级弹窗入口。该方案会制造二次弹窗和重复信息，不符合工作台右侧栏位作为站内工具运行区的设计目标，因此旧弹窗入口、组件和样式在迁移完成后移除。

### 决策 4：文档中心作为外部工具，只在右侧提供跳转动作

文档中心不嵌入、不代理、不管理业务数据。左侧文档中心项只负责选择工具；右侧外部工具栏位展示书架图标、外部系统说明、配置状态和主跳转按钮。配置 `documentCenterUrl` 时按钮使用新标签页打开并设置 `noopener noreferrer`；未配置时右侧按钮禁用，左侧列表项也呈现禁用或未配置状态。

替代方案：左侧文档中心项直接跳转。该方案与现有按钮行为接近，但与“右侧栏位区分外部和内部工具”的设计目标冲突，也不利于用户在离站前得到明确提示。

### 决策 5：响应式布局使用桌面左右栏、移动端上下栏

桌面端使用左右栏，左侧固定工具列表，右侧为当前工具内容。移动端使用上下结构：顶部为工具选择列表或横向工具条，下方为当前工具栏位，面板宽度控制在视口安全范围内。移动端不强制保留桌面的双栏比例，优先保障触控面积和文本不溢出。

替代方案：移动端仍使用左右栏。该方案实现简单，但列表和内容都会过窄，特别是悦灵输入区和服务状态摘要容易拥挤。

## Risks / Trade-offs

- [Risk] 快捷面板同时承载工具选择和工具内容，可能比原右下角列表更重。→ 限制右侧为轻量 UI，避免长说明和完整弹窗嵌套。
- [Risk] 文档中心点击路径从“一点即跳转”变成“选择后点击跳转按钮”。→ 左侧使用外部跳转标记，右侧主按钮清晰写明“打开文档中心”，降低额外步骤带来的困惑。
- [Risk] 悦灵助手和服务状态的右侧栏位与旧弹窗出现重复逻辑。→ 快捷工具不再挂载或触发旧弹窗，站内工具统一在工作台右侧栏位展示。
- [Risk] 服务状态在面板内信息过多。→ 面板展示摘要和高频信息，完整维护说明仍由维护页承载。
- [Risk] 移动端居中面板遮挡页面内容。→ 使用适配视口的最大宽高、内部滚动和明显关闭方式，支持点击遮罩与 Esc 关闭。

## Migration Plan

1. 重构快捷工具组件结构，先保留现有触发器数据输入和事件行为。
2. 新增居中工作台面板状态、左侧工具列表和右侧工具栏位。
3. 将文档中心迁移为外部工具右侧跳转栏位，保持 URL、禁用态和安全打开策略。
4. 将悦灵助手和服务状态迁移为右侧站内工具 UI，并移除从快捷工具打开额外弹窗的行为。
5. 更新 docs 文档与 OpenSpec spec，验证桌面端和移动端视觉、键盘关闭、禁用态和外部跳转。

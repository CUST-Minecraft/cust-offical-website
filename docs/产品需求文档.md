# 长春理工大学 Minecraft 社团官网产品需求文档

## 1. 项目定位

长春理工大学 Minecraft 社团官网用于展示社团形象、发布社团信息、介绍服务器内容，并为游客、校内学生、潜在新成员和社员提供统一的公开访问入口。

系统由两部分组成：

- 官网前台：面向游客、校内学生、校外访问者和潜在新成员。
- 内容后台：由 Strapi Admin 承担，面向内容管理员维护官网公开内容。

皮肤站和文档中心是独立系统，官网分别提供公开外链入口。资源包、整合包、地图和文件下载通过 QQ 群等社群渠道分发，不在官网内建设下载服务。第一阶段允许使用 Strapi 作为 CMS 系统管理内容；后续可在内容模型稳定后迁移为自研后台。

## 2. 核心目标

- 建立社团统一的线上展示入口。
- 展示社团介绍、活动、公告、动态、社员介绍、服务器信息和作品内容。
- 在 Header 提供皮肤站公开跳转入口。
- 在快捷工具工作台面板中提供文档中心公开跳转入口，并区分外部工具与站内工具。
- 支持内容管理员通过独立 CMS 维护官网内容。
- 形成可长期维护、可扩展的内容管理体系。

## 3. 用户角色

| 角色 | 说明 | 核心权限 |
| --- | --- | --- |
| 游客 | 公开访问者 | 浏览公开页面，访问皮肤站和文档中心外链 |
| 社员 | 社团成员 | 浏览公开页面，访问文档中心外链，通过社群渠道获取下载内容 |
| 内容管理员 | 具有 CMS 权限的维护者 | 通过独立 CMS 管理活动、公告、动态、社员介绍等内容 |
| 超级管理员 | CMS 或基础设施最高权限维护者 | 管理 CMS 内容、站点配置和部署环境 |

普通社员默认不能进入内容后台，也不能发布、编辑或删除官网公开内容。官网不维护账号注册、登录、会话或角色权限体系。

## 4. 官网前台页面

本节描述官网前台需要承载的展示内容。是否在第一阶段拆成独立页面，以本文档“第一阶段范围”和详细设计文档为准。

### 4.1 首页

首页承担第一印象和主要入口功能。

应展示：

- 社团品牌标识。
- Hero 主视觉。
- 社团简介。
- 近期活动。
- 最新公告。
- 最新动态。
- 服务器状态或服务器介绍。
- 精彩瞬间或作品展示。
- 社员介绍入口。
- 加入社团入口。
- Header 皮肤站外链入口。
- 快捷工具工作台中的文档中心外链入口。
- 页脚联系方式。

### 4.2 社团介绍页

用于说明社团背景、社团方向、社团文化和主要分组。

应展示：

- 社团简介。
- 社团文化或口号。
- 主要分组，例如建筑组、红石组、活动组、运维组。
- 社团服务器或代表性项目。
- 加入引导。

### 4.3 社团活动页

用于展示近期活动和历史活动。

活动内容应包含：

- 活动标题。
- 活动日期。
- 活动状态。
- 活动简介。
- 活动封面图。
- 活动详情。
- 报名入口或外链。

### 4.4 社团公告页

用于发布正式通知、服务器维护说明、活动结果和重要更新。

公告内容应包含：

- 公告标题。
- 发布时间。
- 公告分类。
- 正文内容。
- 发布状态。
- 置顶设置。

公告具有正式通知属性，应与社团动态区分。

### 4.5 社团动态页

用于发布社团博文、社团日常、服务器记录、成员创作进展和活动花絮。

动态内容应包含：

- 动态标题。
- 发布时间。
- 分类标签。
- 封面图或配图。
- 正文内容。
- 作者或发布人。
- 发布状态。

### 4.6 社员介绍页

用于展示社团成员、分组和代表性成果。

社员展示内容应包含：

- 展示名。
- 所属分组。
- 简介。
- 头像或皮肤形象。
- 代表作品或参与活动。
- 展示状态。

第一阶段不展示真实姓名、学号、手机号等敏感信息。社员公开资料默认由管理员维护。

### 4.7 服务器信息展示

用于展示服务器状态和玩法信息。

应展示：

- 服务器名称。
- 服务器地址。
- 支持版本。
- 游戏模式。
- 在线状态。
- 规则说明。
- 加入服务器方式。

第一阶段服务器状态可由管理员手动维护；后续可接入真实服务器状态查询。

### 4.8 加入我们页

用于承接新成员转化。

应展示：

- 加入方式。
- QQ 群或其他联系方式。
- 入社说明。
- 服务器加入条件。
- 常见问题。

## 5. 外部服务边界

- 皮肤站是独立系统。官网 Header 展示“皮肤站”按钮，使用地狱门图标，点击后直接跳转到配置的皮肤站网址。
- 文档中心是独立系统。官网快捷工具工作台展示“文档中心”外部工具入口，使用书架方块风格图标；访问者选择该工具后，右侧栏位展示外部系统说明和跳转按钮，点击跳转按钮后打开配置的文档中心网址；未配置网址时展示禁用态。
- CMS 是独立内容后台。内容管理员直接访问 Strapi Admin 或后续后台系统，不通过官网中转。
- 下载服务不纳入官网范围。资源包、整合包、地图和文件分发通过 QQ 群等社群渠道完成。

## 6. 内容管理需求

后台内容系统采用类 Strapi 的 Headless CMS 设计方式，第一阶段允许使用 Strapi Admin 承担内容管理能力。

后台应支持维护：

- 站点基础信息。
- 皮肤站和文档中心等外部入口地址。
- 首页内容。
- 社团介绍。
- 社团活动。
- 社团公告。
- 社团动态。
- 社员介绍。
- 加入我们页。
- 图片、附件和作品相册。
- 服务器展示信息。

具体内容模型、字段、接口和媒体规范以详细设计文档为准。

## 7. 设计边界

- 产品需求文档只描述系统目标、用户角色、页面范围和功能边界。
- 技术栈、部署组成和整体架构见总体设计文档。
- 页面详细设计、接口、数据模型、权限、缓存、SEO、媒体规范见详细设计文档。
- 后续自研后台规划见自研后台设计文档。
- 开发风格、注释、命名、提交规范见开发规范文档。

## 8. 第一阶段范围

第一阶段优先完成：

- 官网首页。
- 社团介绍页。
- 活动列表与详情。
- 公告列表与详情。
- 社团动态列表与详情。
- 社员介绍页。
- 加入我们页。
- Header 皮肤站公开外链入口。
- 快捷工具工作台文档中心公开外链入口。
- 404 页面。
- 维护提示页。
- 服务器信息展示，第一阶段可并入首页或社团介绍页。
- 基础内容管理后台。
- 媒体上传和选择。

第一阶段暂缓：

- 独立服务器信息页。
- 在线报名审核。
- 白名单自动审核。
- 作品投稿。
- 评论、点赞、论坛。
- 实时聊天。
- 复杂审核流。
- 内容版本对比。
- 真实服务器状态查询。

## 9. 当前实现完成度

本节用于记录当前仓库实现与第一阶段范围的对齐状态，后续需求变动时应同步更新本文档和详细设计文档。

### 9.1 已基本完成

- Nuxt 3 前端工程已建立，页面路由覆盖首页、社团介绍、活动列表与详情、公告列表与详情、社团动态列表与详情、社员介绍、加入我们、维护页和 404 错误页。
- 像素风视觉系统已通过 Tailwind CSS、自定义 CSS、PNG/SVG 素材和复用组件落地。
- 全站导航、页脚、全站搜索浮层、快捷工具、服务状态、文档中心入口和悦灵助手入口已完成前端交互。
- Strapi 5 内容模型已在 `strapi-models/` 中建立，覆盖站点配置、首页、社团介绍、加入我们、活动、公告、社团动态、社员资料、图库和标签。
- Nuxt Server Routes 已建立公开内容接口，前端页面通过自有 API 访问数据，不直接调用 Strapi 原始 API。
- 公开详情页已使用 `slug` 作为访问标识。
- Header 已规划提供皮肤站公开外链入口。

### 9.2 部分完成

- 皮肤站入口改为 Header 公开外链；皮肤站自身处理账号和访问控制，官网不管理外部系统业务数据。
- 文档中心入口作为快捷工具工作台中的外部工具公开外链；文档中心自身处理账号、权限、文档编辑和访问控制，官网不托管、不代理、不管理文档业务数据。
- 服务状态展示已支持由站点配置维护多项服务状态；真实 Minecraft 服务器在线状态查询尚未接入。
- 悦灵助手已有前端入口、离线提示、常用指令和 Agent 服务健康检查接口；真实对话服务和知识检索能力尚未接入。

### 9.3 待生产接入

- Strapi 生产实例、PostgreSQL、对象存储、CDN、反向代理和生产环境配置。
- CMS 内容录入、媒体上传、真实外部控制台地址配置和缓存策略配置。
- `sitemap.xml`、`robots.txt`、生产 SEO、CDN 缓存刷新和日志备份策略。
- 后续自研后台、活动报名、白名单审核、作品投稿、评论互动等扩展能力仍不属于第一阶段已完成范围。

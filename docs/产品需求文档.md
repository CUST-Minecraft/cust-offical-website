# 长春理工大学 Minecraft 社团官网产品需求文档

## 1. 项目定位

长春理工大学 Minecraft 社团官网用于展示社团形象、发布社团信息、介绍服务器内容，并为游客、校内学生、潜在新成员和社员提供统一的公开访问入口。

系统由两部分组成：

- 官网前台：面向游客、校内学生、校外访问者和潜在新成员。
- 内容后台：由 Strapi Admin 承担，面向内容管理员维护官网公开内容。

皮肤站、文档中心和 MUA 官网是独立系统，官网分别提供公开外链入口。资源包、整合包、地图和文件下载通过 QQ 群等社群渠道分发，不在官网内建设下载服务。第一阶段允许使用 Strapi 作为 CMS 系统管理内容；后续可在内容模型稳定后迁移为自研后台。

## 2. 核心目标

- 建立社团统一的线上展示入口。
- 展示社团介绍、活动、公告、动态、社员介绍、服务器信息和作品内容。
- 在 Header 提供皮肤站公开跳转入口。
- 在社团服务工作台面板中提供文档中心公开跳转入口，并区分外部服务与站内服务。
- 在页脚提供像素风品牌区、外联栏目和关于我们栏目，承载 MUA 官网等公开外链。
- 支持内容管理员通过独立 CMS 维护官网内容。
- 支持内容管理员在维护/预览场景通过官网社团服务按钮上方的“维护模式”提示按钮识别前台内容对应的数据模型、字段名称和页面用途。
- 形成可长期维护、可扩展的内容管理体系。
- 明确官网内容管理边界：系统需要识别、筛选、排序、跳转或复用的内容使用结构化数据模型；活动详情、公告正文、社团动态正文、社团介绍长文等阅读正文使用 Markdown 或等价富文本。

## 3. 用户角色

| 角色 | 说明 | 核心权限 |
| --- | --- | --- |
| 游客 | 公开访问者 | 浏览公开页面，访问皮肤站和文档中心外链 |
| 社员 | 社团成员 | 浏览公开页面，访问文档中心和 MUA 官网等外链，通过社群渠道获取下载内容 |
| 内容管理员 | 具有 CMS 权限的维护者 | 通过独立 CMS 管理活动、公告、动态、社员介绍等内容 |
| 超级管理员 | CMS 或基础设施最高权限维护者 | 管理 CMS 内容、站点配置和部署环境 |

普通社员默认不能进入内容后台，也不能发布、编辑或删除官网公开内容。官网不维护账号注册、登录、会话或角色权限体系。

## 4. 官网前台页面

本节描述官网前台需要承载的展示内容。是否在第一阶段拆成独立页面，以本文档“第一阶段范围”和详细设计文档为准。

### 4.1 首页

首页承担第一印象和主要入口功能。

应展示：

- 社团品牌标识。
- Hero 主视觉。
- 社团简介。
- 近期活动。
- 最新公告。
- 最新动态。
- 服务器状态或服务器介绍。
- 精彩瞬间或作品展示。
- 社员介绍入口。
- 加入社团入口。
- Header 皮肤站外链入口。
- 社团服务工作台中的文档中心外链入口。
- 像素风页脚品牌区、外联栏目和关于我们栏目。

### 4.2 社团介绍页

用于以品牌故事方式说明社团身份、起点、主要行动和参与方向，让访问者理解长春理工大学 Minecraft 社团后继续前往加入、活动或社员介绍等公开页面。

应展示：

- 认识我们：社团名称、摘要、头图和核心口号。
- 我们的起点：社团介绍正文，说明社团如何从 Minecraft 兴趣延伸到校园记忆、创作和朋友。
- 我们的行动：校园复刻、服务器共建、活动与创作等社团主要行动。
- 我们的方向：主要参与方向，例如建筑、红石、活动、运维。
- 继续了解：加入我们、社团活动、社员介绍等站内公开入口。

社团介绍页内容按板块维护，一条 `AboutPage.sections` 数据对应一个前台板块。后台可维护板块标题、摘要、正文、卡片、链接、排序和启用状态；前台只支持固定板块类型，不提供自由页面搭建。

社团介绍页不作为服务器连接参数或加入流程说明页；服务器共建可作为社团行动展示，服务器地址、版本、模式和具体加入流程由更合适的页面或服务入口承载。

### 4.3 社团活动页

用于展示近期活动和历史活动。

活动内容应包含：

- 活动标题。
- 活动日期。
- 活动状态。
- 活动简介。
- 活动封面图。
- 活动详情。
- 报名入口或外链。

### 4.4 社团公告页

用于发布正式通知、服务器维护说明、活动结果和重要更新。

公告内容应包含：

- 公告标题。
- 发布时间。
- 公告分类。
- 正文内容。
- 发布状态。
- 置顶设置。

公告具有正式通知属性，应与社团动态区分。

### 4.5 社团动态页

用于发布社团博文、社团日常、服务器记录、成员创作进展和活动花絮。

动态内容应包含：

- 动态标题。
- 发布时间。
- 分类标签。
- 封面图或配图。
- 正文内容。
- 作者或发布人。
- 发布状态。

### 4.6 社员介绍页

用于展示社团成员、分组和代表性成果。

社员展示内容应包含：

- 展示名。
- 所属分组。
- 简介。
- 头像或皮肤形象。
- 代表作品或参与活动。
- 展示状态。

第一阶段不展示真实姓名、学号、手机号等敏感信息。社员公开资料默认由管理员维护。

### 4.7 服务器信息展示

用于展示服务器状态和玩法信息。

应展示：

- 服务器名称。
- 服务器地址。
- 支持版本。
- 游戏模式。
- 在线状态。
- 规则说明。
- 加入服务器方式。

第一阶段服务器状态可由管理员手动维护；后续可接入真实服务器状态查询。

### 4.8 加入我们页

用于承接长期开放加入的新成员转化，以流程引导方式说明如何进入社团。

应展示：

- 加入流程。
- 可选择的参与身份，例如建筑共创、红石机制、活动策划、服务器协作、内容记录或轻松游玩。
- 加入方式，例如 QQ 群、外部申请表、社团联系人或先查看活动。
- 基本规则、服务器白名单和公开资料隐私说明。
- 流程步骤中的可选图片、说明和动作入口。
- 常见问题。

第一阶段不在官网内收集申请人数据，不实现站内报名审核、白名单审核或申请状态查询。

## 5. 外部服务边界

- 皮肤站是独立系统。官网 Header 展示“皮肤站”按钮，使用地狱门图标，点击后直接跳转到配置的皮肤站网址。
- 文档中心是独立系统。官网社团服务工作台展示“文档中心”外部服务入口，使用书架方块风格图标；访问者选择该服务后，右侧栏位展示外部系统说明和跳转按钮，点击跳转按钮后打开配置的文档中心网址；未配置网址时展示禁用态。社团服务触发器使用工作台方块作为整体隐喻，并以“x 项服务可用”提示内部包含多个服务。
- MUA 官网是独立外部网站。官网页脚“外联”栏目展示“MUA 官网”入口，点击后以公开外链方式打开配置的网址；官网不代理、不嵌入、不抓取、不管理 MUA 官网内容。
- 皮肤站、文档中心、MUA 官网和悦灵助手等入口统一作为外部服务或服务入口配置，由外部服务数据模型维护名称、URL、图标、启用状态、展示位置和排序；官网只负责公开入口展示和跳转。
- CMS 是独立内容后台。内容管理员直接访问 Strapi Admin 或后续后台系统，不通过官网中转。
- 下载服务不纳入官网范围。资源包、整合包、地图和文件分发通过 QQ 群等社群渠道完成。

## 6. 内容管理需求

后台内容系统采用类 Strapi 的 Headless CMS 设计方式，第一阶段允许使用 Strapi Admin 承担内容管理能力。

后台应支持维护：

- 站点基础信息，包括站点名称、短名称、英文名、Logo、导航、页脚版权、页脚署名和关于我们链接。
- 维护页配置，包括维护开关、维护标题、维护说明、预计恢复时间和服务状态列表。
- 皮肤站、文档中心、MUA 官网、悦灵助手等外部服务或服务入口，包括名称、URL、图标、启用状态、展示位置和排序。
- 首页内容。
- 社团介绍。
- 社团活动。
- 社团公告。
- 社团动态。
- 社员介绍。
- 加入我们页。
- 图片、附件和作品相册。
- 服务器展示信息。

具体内容模型、字段、接口和媒体规范以详细设计文档为准。

内容录入规则：

- 标题、摘要、时间、状态、标签、图片、链接、排序、精选关系、导航、页脚、服务入口、维护开关、页面组件配置、流程步骤图片、流程步骤明细条目和流程步骤动作入口必须使用结构化字段。
- 活动详情、公告正文、社团动态正文、社团介绍正文、服务器说明、加入引导、入社介绍和服务器加入说明使用 Markdown 或等价富文本正文。
- 摘要、FAQ 回答、流程步骤说明、流程步骤图片说明、流程步骤明细条目和卡片短描述保持普通文本，不使用 Markdown 拼装页面结构。
- 官网可在维护/预览场景提供内容字段提示层；内容管理员点击页面左下角的 Minecraft 风格维护模式图标按钮后，可通过 hover 前台内容查看对应数据模型、字段名称和页面用途。按钮仅展示钻石镐风格 SVG 图标，宽度和高度与社团服务按钮高度持平，并与社团服务按钮保持一致的页尾避让行为。字段提示不得面向普通访问者展示，也不得改变页面原有排版。

## 8. 第一阶段范围

第一阶段优先完成：

- 官网首页。
- 社团介绍页。
- 活动列表与详情。
- 公告列表与详情。
- 社团动态列表与详情。
- 社员介绍页。
- 加入我们页。
- Header 皮肤站公开外链入口。
- 社团服务工作台文档中心公开外链入口。
- 像素风页脚品牌面板和页脚外联入口。
- 404 页面。
- 维护提示页。
- 服务器信息展示，第一阶段可并入首页或社团介绍页。
- 基础内容管理后台。
- 媒体上传和选择。

第一阶段暂缓：

- 独立服务器信息页。
- 在线报名审核。
- 白名单自动审核。
- 作品投稿。
- 评论、点赞、论坛。
- 实时聊天。
- 复杂审核流。
- 内容版本对比。
- 真实服务器状态查询。

## 9. 当前实现完成度

本节用于记录当前仓库实现与第一阶段范围的对齐状态，后续需求变动时应同步更新本文档和详细设计文档。

### 9.1 已基本完成

- Nuxt 3 前端工程已建立，页面路由覆盖首页、社团介绍、活动列表与详情、公告列表与详情、社团动态列表与详情、社员介绍、加入我们、维护页和 404 错误页。
- 像素风视觉系统已通过 Tailwind CSS、自定义 CSS、PNG/SVG 素材和复用组件落地。
- 全站动效系统已规划用于统一页面入场、搜索结果切换、社团服务工作台内部切换和减少动态偏好下的静态反馈。
- 全站导航、全站搜索浮层、社团服务工作台、服务状态、文档中心入口和悦灵助手入口已完成前端交互；页脚将升级为像素风品牌面板并使用结构化链接数据。
- Strapi 5 内容模型已在 `strapi-models/` 中建立，覆盖站点配置、首页、社团介绍、加入我们、活动、公告、社团动态、社员资料、图库和标签。
- Nuxt Server Routes 已建立公开内容接口，前端页面通过自有 API 访问数据，不直接调用 Strapi 原始 API。
- 公开详情页已使用 `slug` 作为访问标识。
- Header 已规划提供皮肤站公开外链入口。

### 9.2 部分完成

- 皮肤站入口改为 Header 公开外链；皮肤站自身处理账号和访问控制，官网不管理外部系统业务数据。
- 文档中心入口作为社团服务工作台中的外部服务公开外链；文档中心自身处理账号、权限、文档编辑和访问控制，官网不托管、不代理、不管理文档业务数据。
- 服务状态展示已支持由站点配置维护多项服务状态；真实 Minecraft 服务器在线状态查询尚未接入。
- 悦灵助手已有前端入口、离线提示、常用指令和 Agent 服务健康检查接口；真实对话服务和知识检索能力尚未接入。

### 9.3 待生产接入

- Strapi 生产实例、PostgreSQL、对象存储、CDN、反向代理和生产环境配置。
- CMS 内容录入、媒体上传、真实外部控制台地址配置和缓存策略配置。
- `sitemap.xml`、`robots.txt`、生产 SEO、CDN 缓存刷新和日志备份策略。
- 后续自研后台、活动报名、白名单审核、作品投稿、评论互动等扩展能力仍不属于第一阶段已完成范围。
